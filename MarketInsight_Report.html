Abstract

Equity research and investment analysis are traditionally fragmented across multiple isolated platforms: specialized charting tools, balance sheet ratio screeners, news feeds, and generic AI chat assistants. Commercial institutional workstations like the Bloomberg Terminal or FactSet resolve this fragmentation by unifying real-time data and analytics, but their prohibitive subscription costs (exceeding twenty-four thousand dollars annually) place them out of reach for retail investors, finance students, and independent analysts. At the same time, standard conversational Large Language Models suffer from static training cutoffs, possess no native connection to live financial feeds, and cannot reliably compute deterministic formulas such as the Relative Strength Index (RSI) or Discounted Cash Flow (DCF) intrinsic equity valuations.

To resolve these structural disadvantages, this project presents MarketInsight v2.0, an institutional-grade, full-stack quantitative financial intelligence platform. MarketInsight integrates an autonomous LangGraph ReAct AI agent powered by Google Gemini with 16 real-time financial execution tools, an asynchronous FastAPI streaming server utilizing Server-Sent Events (SSE), and a modern React 18 and TypeScript Quant Workstation styled in an institutional dark aesthetic. The platform features an AI Chat Terminal with transparent audit trail tool badges, an interactive zero-dependency SVG Chart Studio with hover crosshairs and momentum oscillators, an intrinsic DCF Valuation Simulator with dynamic growth and discount rate sliders, sector treemap heatmaps, sparkline watchlists, two-asset duel arenas, and browser-native voice transcription. All modules have been deployed, fully verified, and open-sourced under an MIT license.

Retail investors and individual traders face severe structural barriers when conducting equity analysis:

Retail participants, by contrast, frequently rely on delayed quotes, fragmented web articles, and promotional social media feeds.

Standard LLMs either hallucinate outdated values or disclaim any knowledge of current events.

Chapter 2 • Background and Concepts

2.1 Financial Intelligence and Information Asymmetry

Financial markets operate on the principle of market efficiency, wherein prices reflect all publicly available information. However, in practice, the latency and cognitive effort required to acquire, normalize, and interpret financial statements create significant informational disparities. Retail investors often make decisions based on superficial indicators without analyzing cash flow viability or margin of safety. MarketInsight addresses this disparity by automating the tedious stages of financial data gathering and fundamental calculation.

2.2 Multi-Tool Agent Systems and ReAct Architecture

A ReAct (Reasoning and Acting) agent combines language model reasoning with external action execution. Rather than attempting to answer financial queries from frozen parametric memory, the agent operates in an iterative state loop:

  • Thought Phase: The language model analyzes the user query, determines what information is missing, and formulates an actionable plan.
  • Action Phase: The agent issues a structured call to an external tool (e.g., retrieving an income statement or current stock quote).
  • Observation Phase: The tool executes against a live API and returns its output directly to the agent's context window.
  • Synthesis Phase: The agent repeats this cycle across multiple tools until it has collected sufficient facts to compose a comprehensive, verified answer.

2.3 Technical Analysis and Momentum Oscillators

Technical analysis evaluates equities through historical price and volume trends rather than business fundamentals. The Relative Strength Index (RSI), developed by J. Welles Wilder, is a momentum oscillator measuring the speed and change of price movements over a 14-period lookback window. Values below 30 indicate an oversold asset ripe for a bullish reversal, while values above 70 indicate an overbought asset vulnerable to a correction. Moving average crossovers (such as the 20-day and 50-day Simple Moving Averages) provide trend confirmation, signaling bullish momentum when the short-term average crosses above the medium-term average (Golden Cross).

2.4 Intrinsic Equity Valuation through Discounted Cash Flow

Fundamental valuation holds that an asset's true economic value is equal to the present value of all future cash flows it generates for its owners. The Discounted Cash Flow (DCF) model accomplishes this by projecting Free Cash Flow across a multi-year horizon, calculating a Terminal Value assuming perpetual growth, and discounting these future sums back to present value using the company's Weighted Average Cost of Capital (WACC). Comparing intrinsic value per share against current market price establishes the Margin of Safety, protecting investors against valuation risk.

2.5 Real-Time Streaming via Server-Sent Events

Unlike traditional request-response architectures where the client must wait for an entire multi-paragraph AI response to complete, Server-Sent Events (SSE) establish a persistent, unidirectional HTTP connection. The backend streams tokens to the browser as they are generated, achieving sub-second Time-to-First-Token (TTFT) and providing a responsive typing interface essential for real-time applications.

4.3 Mathematical Formulations of the Quantitative Engine

A. Relative Strength Index (RSI)

The Relative Strength Index evaluates momentum over a standard 14-period lookback window:

RSI = 100 - [ 100 / (1 + RS) ]

where RS = Average Gain over 14 periods / Average Loss over 14 periods
Decision Boundaries: RSI < 30 (Oversold / Buy Signal) | RSI > 70 (Overbought / Sell Signal)

B. Discounted Cash Flow (DCF) Model

The intrinsic valuation model projects Free Cash Flow ($FCF$) across a 5-year forecast horizon and discounts at the Weighted Average Cost of Capital ($WACC$ or $r$):

Present Value of Projected Cash Flows = Σ [ FCF_0 × (1 + g)^t / (1 + r)^t ] for t = 1 to 5

Terminal Value (Gordon Growth) = [ FCF_5 × (1 + g_T) ] / (r - g_T)   (where g_T = 3.0%)

Total Intrinsic Market Equity Value = PV of Cash Flows + [ Terminal Value / (1 + r)^5 ]

Intrinsic Value Per Share = Total Intrinsic Market Value / Total Diluted Shares Outstanding

Margin of Safety Percentage = [ (Intrinsic Value - Current Price) / Current Price ] × 100%

C. Simple Moving Average (SMA)

SMA_k = (1 / k) × Σ P_(t - i)   for i = 0 to k - 1   (computed for k = 20 and k = 50)
Golden Cross: SMA_20 crosses above SMA_50 (Bullish Breakout Signal)
Death Cross: SMA_20 crosses below SMA_50 (Bearish Breakdown Signal)

Chapter 5 • Implementation Details

5.1 Backend Gateway Implementation

The backend application is implemented using the FastAPI asynchronous framework, executed via the Uvicorn ASGI server. The core gateway manages six primary endpoints:

  • POST /api/chat: The primary conversational endpoint. Receives a user prompt, initializes the LangGraph ReAct agent stream, and pipes generated output tokens through a Server-Sent Events (SSE) generator. Crucially, the generator contains a filtering pipeline that inspects each chunk in the execution stream, removing raw internal tool invocation payloads so that only polished, user-facing analytical sentences reach the client.
  • GET /api/chart-data/{ticker}: Accepts an equity ticker and timeframe parameter (1mo, 3mo, 1y, 5y). Retrieves historical OHLCV data, calculates the 14-period RSI oscillator, computes 20-day and 50-day moving averages, extracts real free cash flow figures from annual cash flow statements, and compiles a comprehensive JSON payload for the frontend Chart Studio.
  • GET /api/market-heatmap: Compiles real-time performance percentages and market capitalizations across key sectors (Technology, Financial Services, Healthcare, Energy, and Consumer Discretionary) to feed the interactive SVG treemap.
  • GET /api/market-pulse: Pulls real-time headline index levels for NIFTY 50, BSE SENSEX, S&P 500, and NASDAQ 100 to populate the top ticker banner.
  • GET /api/stock-quote/{ticker}: Delivers lightweight, sub-second quotes (price, change, percentage change, and volume) for the dynamic Watchlist.
  • GET /: Provides an API discovery and health status endpoint confirming system availability.

5.2 AI Agent Subsystem and Tool Integration

The reasoning subsystem uses the Google Gemini language model (configured via the production model identifier gemini-flash-lite-latest). The model is bound to the 16 Python financial tools through the LangGraph agent creation runtime. When a user requests a comparison between two companies, Gemini evaluates both entities, invokes corporate search tools to resolve ticker symbols, initiates simultaneous balance sheet and analyst ratings inspections, and synthesizes the comparative findings into a formatted markdown table.

5.3 Frontend Quant Workstation Design System

The frontend interface is engineered as an institutional single-page workstation using React 18 and TypeScript, compiled via Vite. The visual theme is inspired by professional financial terminals (such as the Bloomberg Terminal and Koyfin), utilizing a high-contrast dark color palette (deep blacks, slate gray borders, electric cyan highlights, and neon green/crimson gain and loss indicators). Key design decisions include:

  • Zero External Chart Libraries: To maintain complete control over rendering performance and eliminate heavyweight dependencies (such as Chart.js or D3.js), all candlestick bars, cubic bezier trendlines, volume bars, and hover crosshair lines are rendered using custom, mathematically calculated SVG vectors.
  • Polymorphic SSE Stream Parser: The React client maintains an asynchronous stream reader that parses incoming SSE data lines, buffering text fragments to create a fluid, real-time typing animation while concurrently parsing tool execution metadata to render audit trail badges.
  • Native Browser Voice Transcription: Spoken inquiries are captured directly using the Web Speech API (webkitSpeechRecognition), transcribing voice audio into text in real time with zero external network overhead or cloud billing costs.

Chapter 7 • Challenges Faced & Solutions

7.1 Technical Challenges and Applied Engineering Solutions

Challenge 1: Deprecation of Legacy Gemini Endpoints and HTTP 503 Overload Errors
During development, initial attempts to use legacy models (such as gemini-2.0-flash) failed with HTTP 404 NOT FOUND errors due to model retirement, while newer preview models (such as gemini-3.8-flash) intermittently returned HTTP 503 SERVICE UNAVAILABLE during peak demand windows.
Applied Solution: Conducted comprehensive availability and latency profiling across all active Google DeepMind endpoints. Identified gemini-flash-lite-latest as the most stable, low-latency production model supporting native LangGraph tool calling with zero availability drops.
Challenge 2: Polymorphic Structured SSE Token Formats in Gemini Responses
Standard LLM wrappers emit plain string tokens during streaming. However, Gemini's function-calling streaming generator emits polymorphic content arrays containing dictionaries (such as [{'type': 'text', 'text': '...'}]). Attempting to serialize or concatenate these objects directly caused empty responses or client-side JSON parsing crashes.
Applied Solution: Engineered a robust recursive content extractor (extract_text()) in main.py that validates whether incoming tokens are strings, dictionaries, or structured objects, extracting pure string text prior to Server-Sent Event formatting.
Challenge 3: Tool Execution Data Bleeding into User-Facing Streaming Outputs
When the LangGraph ReAct agent calls external tools (e.g., retrieving prices or balance sheets), intermediate ToolMessage records are broadcast through the execution stream. Without filtering, raw internal ticker lookups and JSON fragments appeared in user chat bubbles before the final response was written.
Applied Solution: Built a strict type inspection filter in the asynchronous SSE generator that intercepts and discards any chunk where the message type equals "tool" or matches the ToolMessage class signature, preserving only the final conversational response for the user.
Challenge 4: Yahoo Finance HTTP 429 Rate Limiting and Deprecated Price Attributes
Frequent automated requests to Yahoo Finance ticker lookup endpoints triggered HTTP 429 (Too Many Requests) errors. Concurrently, the standard info['regularMarketPrice'] attribute frequently returned null values due to upstream changes.
Applied Solution: Injected custom browser-emulating request headers (User-Agent: Mozilla/5.0...) to eliminate scraper detection, and implemented a three-tier price discovery fallback chain in get_stock_price that queries fast_info.last_price first, then the info dictionary, and finally the latest historical daily close.

Appendix • Installation and Execution Guide

A.1 Prerequisites

To run MarketInsight locally, the host system requires Python 3.11+, Node.js 18+, Git, and a Google AI Studio API key.

A.2 Step-by-Step Execution Guide

  1. Clone the Repository: Clone the project files from GitHub using Git.
  2. Configure Environment Secrets: Create a local .env file modeled after .env.example, setting GOOGLE_API_KEY and configuring GEMINI_MODEL=gemini-flash-lite-latest.
  3. Set Up Python Virtual Environment: Initialize a Python virtual environment, activate it, and install required libraries (FastAPI, Uvicorn, LangGraph, yfinance) using pip.
  4. Start Backend Server: Execute python main.py from the project root. The FastAPI server starts at http://localhost:8000.
  5. Start Frontend Workstation: Navigate into the frontend/ folder, install dependencies using npm install, and start the development server using npm run dev. The workstation opens at http://localhost:3000.
